  2. 2. applyCoupon computes the discount from the coupon rules observed

    TENPCT is 10% off, capped at $20. For subtotal 55 that is 5.5, under the cap.

    src/pricing.js:9-26

    export function applyCoupon(cart, code) {
  const rule = COUPONS[code];
  if (!rule) {
    return { ok: false, reason: "unknown coupon" };
  }
  const subtotal = cart.totals.subtotal;
  let discount;
  if (rule.kind === "fixed") {
    discount = rule.value;
  } else {
    discount = Math.min(round2((subtotal * rule.value) / 100), rule.cap);
  }
  discount = round2(Math.min(discount, subtotal));
  cart.coupon = code;
  cart.totals.discount = discount;
  cart.totals.total = round2(subtotal - discount);
  return { ok: true, code, discount, total: cart.totals.total };
}

  5. 5. recompute resets the discount to 0 while recalculating observed

    reload() calls recompute(cart) and never re-applies the stored coupon, so the discount is gone after a reload even though the coupon label survives.

    src/cart.js:16-21

    export function recompute(cart) {
  const subtotal = cart.items.reduce((sum, item) => sum + item.price * item.qty, 0);
  cart.totals.subtotal = round2(subtotal);
  cart.totals.discount = 0;
  cart.totals.total = round2(subtotal);
}

locateWhere is the actual fault that loses the discount on reload?

Code to inspect: src/store.js:9-17 · src/cart.js:16-21

Options

Hint 1

The checkout run proves applyCoupon and printing are fine: totals.total was 49.5 before saving.

Hint 2

recompute's reset is a documented contract: callers re-apply coupons after changing items. Which caller fails to do that?

Explanation (spoiler)

The recorded runs narrow it down: checkout prints a correct discounted total, so pricing and printing work; after reload the coupon code is still on the cart but the discount is 0. reload() in store.js rebuilds totals via recompute() and never re-applies the stored coupon. Fixing it means re-applying the coupon inside reload (or persisting the applied discount), not changing recompute's contract.
